# Skill: documentation

**Goal:** add or update user/developer documentation and build the Sphinx site locally.

Docs are reStructuredText under `docs/source/`, rendered by Sphinx with the PDJ theme and
published on Read the Docs (<https://opengate-python.readthedocs.io/>).

CI ignores changes under `docs/**` (`paths-ignore` in `.github/workflows/main.yml`), so a
docs-only PR does not trigger the build — but a broken reference *will* break the Read the
Docs build. Build locally.

---

## 1. Layout

```
docs/
├── Makefile, make.bat          # `make html`
├── requirements.txt            # sphinx + theme + autoapi + copybutton
└── source/
    ├── conf.py                 # Sphinx config
    ├── index.rst               # top-level toctree
    ├── user_guide/
    │   ├── index.rst
    │   ├── user_guide_installation.rst
    │   ├── user_guide_intro.rst, user_guide_first_simulation.rst
    │   ├── user_guide_<topic>.rst                    (narrative pages)
    │   └── user_guide_reference_<topic>.rst          (exhaustive references)
    └── developer_guide/
        ├── index.rst
        ├── developer_guide_installation.rst
        ├── developer_guide_contribute.rst
        └── developer_guide_<topic>.rst
```

Convention: `user_guide_reference_*.rst` for exhaustive parameter references,
`user_guide_*.rst` for task-oriented pages.

## 2. Building locally

```bash
cd docs
python -m pip install -r requirements.txt      # sphinx, theme, autoapi, copybutton, ...
make html                                       # output in docs/build/html
```

Open `docs/build/html/index.html` in a browser. Treat warnings (unresolved references,
malformed directives, missing toctree entries) as errors — fix them.

Faster iteration: `sphinx-autobuild` if available, or read the warnings as they appear
without opening the browser.

## 3. Adding a page

1. Create `docs/source/<user_guide|developer_guide>/<name>.rst` using a title + underline
   of matching length, and a hierarchy of `=`, `-`, `~` for sections.
2. **Add it to the toctree** of the corresponding `index.rst` — a page not in a toctree
   produces a warning and is invisible on Read the Docs.
3. Cross-reference with labels instead of hard-coded HTML links where possible.
4. Verify with `make html`.

Typical page skeleton:

```rst
My new feature
==============

Short statement of what the feature does and who needs it.

Usage
-----

.. code:: python

   import opengate as gate

   sim = gate.Simulation()
   ...

Parameters
----------

Note: such and such is only available with X.
```

## 4. Writing rules

- **Code blocks** use `.. code:: python` / `.. code:: bash` and must be runnable (or
  clearly marked as a fragment).
- **Admonitions** for warnings, e.g. `.. warning::`, `.. note::`, `.. tip::`
  (`developer_guide_installation.rst` uses them throughout — copy that style).
- **Relative paths** in examples should point to real files in the repo.
- **Do not duplicate** upstream Geant4 documentation: link to it.
- Keep parameter names exactly as they appear in the code; verify by grepping
  `opengate/` before writing them down. A wrong parameter name in the docs is worse than
  no doc.
- Sphinx pages for the Python API are generated by `sphinx-autoapi`; a docstring in the
  source plus the page's `automodule`/`autoclass` directive is enough to surface it.

## 5. Documentation for a new feature: where to write what

| You changed | Update |
| --- | --- |
| A user-visible parameter or behaviour | the matching `user_guide_reference_*.rst` **and** the narrative page that explains the workflow. |
| A new actor/source | `user_guide_reference_actors.rst` / `user_guide_reference_sources.rst` + a short section in the corresponding `user_guide_*.rst`. |
| The developer install / build | `developer_guide_installation.rst` — and keep it in sync with `.github/workflows/` (Geant4/ITK versions!). |
| The contribution workflow | `developer_guide_contribute.rst`. |
| A new agent-facing convention | this `skills/` directory + the table in `AGENTS.md` (not the Sphinx site). |

## 6. Checklist

- [ ] Page uses the existing naming convention and is listed in its `index.rst` toctree.
- [ ] `cd docs && make html` completes without **new** warnings.
- [ ] Every parameter name in the text was checked against the code.
- [ ] Versions quoted (Geant4, ITK, Python) match `.github/workflows/main.yml`.
- [ ] No build output committed (`docs/build/` is generated).
